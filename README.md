# Afroé — Mobile App (iOS + Android)

Native iOS and Android apps for the [Afroé](https://app.afroe.studio) beauty
marketplace, built with [Capacitor](https://capacitorjs.com/).

## Strategy: native shell over the live web app

The web app (`afrobeautymarket1.2` → Next.js 15, deployed at
`app.afroe.studio`) is heavily server-side (middleware auth, server actions,
API routes), so it **can't be statically exported** and bundled. Instead, this
project is a thin **native shell** that loads the live site inside the native
WebView (`server.url` in [`capacitor.config.ts`](./capacitor.config.ts)).

**What this gives you:**
- Real apps in the App Store and Google Play, reusing 100% of the web codebase.
- Every Vercel deploy is reflected in the app instantly — **no store
  resubmission** for content/logic changes.
- Native capabilities (geolocation, status bar, splash, push later) via
  Capacitor plugins.

**Trade-off:** it's a WebView app, not a native-UI rebuild. If you later want a
fully native experience, this repo can be swapped for Flutter/React Native
while keeping the same Supabase backend.

## Prerequisites

- **Node.js 20+** and npm
- **iOS builds:** macOS + Xcode 15+ (Apple requires a Mac to compile/submit iOS)
- **Android builds:** Android Studio (any OS)
- Apple Developer account ($99/yr) and Google Play Console ($25 one-time) to publish

## Setup

```bash
npm install

# Generate the native projects (run once; requires the platform toolchains)
npm run add:ios
npm run add:android

# Sync web config + plugins into the native projects
npm run sync
```

## Run in the simulators / on device

```bash
npm run open:ios       # opens Xcode → run on a simulator or device
npm run open:android   # opens Android Studio → run on an emulator or device
```

Because `server.url` points at `https://app.afroe.studio`, the app loads the
live production site. To test against a local/preview backend, temporarily
change `server.url` in `capacitor.config.ts` and re-run `npm run sync`.

## App icons & splash

Drop `icon.png` (1024×1024) and `splash.png` (2732×2732) into
[`assets/`](./assets/), then:

```bash
npm run assets
npm run sync
```

## Building for the stores

**iOS** (on macOS):
1. `npm run open:ios`
2. Xcode → set your Team & bundle id (`studio.afroe.app`), bump the version/build
3. Product → Archive → distribute to App Store Connect

**Android:**
1. `npm run open:android`
2. Build → Generate Signed Bundle/APK → **Android App Bundle (.aab)**
3. Upload the `.aab` to the Google Play Console

## ⚠️ Backend changes required in the web app

These live in the **`afrobeautymarket1.2`** repo, not here, but the app depends
on them:

1. **CSP** — `next.config.mjs` sets a strict `Content-Security-Policy`. The
   native WebView origins must be allowed or the shell can break. Add the
   Capacitor origins to `connect-src` / `default-src`:
   ```
   capacitor://localhost  https://localhost  https://app.afroe.studio
   ```
   (iOS uses `capacitor://localhost`, Android uses `https://localhost`.)

2. **Auth** — the web app now supports JWT `Authorization: Bearer` auth on all
   API routes (the `getSession()` → `getUser()` migration, merged in
   `afrobeautymarket1.2#142`). Verify the Supabase cookie login flow works
   inside the WebView; if third-party-cookie restrictions bite, switch the
   mobile session to token-based.

3. **Deep links / OAuth** — configure the `studio.afroe.app` URL scheme +
   Universal Links / App Links so Supabase OAuth returns into the app.

4. **PWA polish** *(recommended)* — add a `manifest.json` + icons in the web
   app's `public/` for a cleaner install and to satisfy store review of the shell.

## ⚠️ App Store payment note

Apple requires **In-App Purchase** for *digital* goods. Physical
services/bookings paid via Mollie are generally fine (guideline 3.1.3), but
confirm your specific flows before submitting to avoid rejection.

## Project layout

```
.
├── capacitor.config.ts   # appId, appName, server.url → live site
├── package.json          # Capacitor deps + helper scripts
├── www/index.html        # local boot/offline fallback splash
├── assets/               # icon.png / splash.png sources (→ npm run assets)
├── ios/                  # generated by `npm run add:ios` (committed after generation)
└── android/              # generated by `npm run add:android` (committed after generation)
```

The `ios/` and `android/` folders are created by `npx cap add` on a machine
with the native toolchains, then committed so signing config and native tweaks
are tracked.
